# Botcraft Studio

Botcraft Studio — Android-конструктор игровых Telegram Mini Apps. APK использует нативный Android-интерфейс на Java Views: в приложении нет боковой веб-навигации и WebView-экрана. Веб-версия остаётся только для браузерного предпросмотра проекта; Android APK собирается отдельно в GitHub Actions.

## Каталог игровых сценариев

- **Квиз-арена** — вопросы для компании и очки.
- **Тап-фабрика** — кликер с улучшениями и рекордами.
- **Мемори-дуэль** — пары карточек на скорость.
- **Словолов** — словесная головоломка.
- **Реакция** — аркада на время реакции.
- **Миссия дня** — ежедневное задание и серия возвращений.

В нативном приложении есть каталог с поиском, создание и локальное хранение проектов, экспорт стартового ZIP и раздел настроек. Проверка обновлений выполняется внутри приложения: APK загружается через Android DownloadManager, а установку подтверждает системный установщик Android. Тихая установка без системного подтверждения Android сторонним приложениям недоступна.

## Разработка

```bash
npm ci
npm run dev
npm run build
```

## Отладочный APK

На каждый push в `arena/**` GitHub Actions собирает debug APK. Артефакт появляется в запуске workflow `Build Android APK`.

## OTA-релизы Android

Android не разрешает стороннему приложению тихо установить APK без подтверждения пользователя. Botcraft может проверять GitHub Releases, открыть загрузку свежего APK, после чего Android покажет системное подтверждение установки. Для непрерывного обновления все релизы должны быть подписаны **одним и тем же приватным ключом**.

Подписанный release workflow находится в `.github/workflows/android-release.yml`. Он запускается push-ем git-тега формата `v1.0.1`, подписывает APK и публикует `botcraft-studio.apk` в GitHub Releases. В **Settings → Secrets and variables → Actions** нужен один секрет `ANDROID_SIGNING_BUNDLE` — JSON-пакет с keystore, паролем и alias. `GITHUB_TOKEN` для публикации релиза GitHub Actions выдаёт автоматически. Сохраните резервную копию signing keystore и пароль в надёжном менеджере паролей: без прежнего ключа Android не примет обновление поверх установленной версии.

Первый signed release использует отдельный ключ от debug APK. Поэтому уже установленную debug-версию нужно удалить и установить первый release APK вручную; следующие signed-релизы можно будет устанавливать поверх предыдущих. Для публикации новой версии увеличьте tag, например `v1.0.2`.

## Сборка Android локально

Нужны Node.js 22, Android Studio/Android SDK и JDK 21:

```bash
npm ci
npm run android:add       # один раз создать android/
npm run android:sync
cd android && ./gradlew assembleDebug
```

Для игры, которая будет работать с реальными рейтингами или мультиплеером, добавьте backend и серверную проверку Telegram `initData`; данные стартовых демо-игр пока хранятся только в текущей сессии.
